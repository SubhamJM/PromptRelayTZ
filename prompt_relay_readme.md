# 🕵️ Prompt Relay: The Hot-Seat Sprint (Murder Mystery Edition)

**Prompt Relay** is a sequential, high-stakes prompt-engineering game designed for live crowds and events. Teams of 3 take turns at a single laptop ("hot seat" style). Each player acts as a link in an AI pipeline to solve a murder mystery. 

*   **Player 1 (The Extractor):** Filters facts from a noisy case file.
*   **Player 2 (The Reconstructor):** Builds a timeline from Player 1's facts.
*   **Player 3 (The Formatter):** Names the killer based on Player 2's timeline and formats it as JSON.

The catch? The AI's system prompts are rigged to fail if the players aren't precise. A live "Roastmaster" AI evaluates the final output and publicly shames the exact teammate who broke the chain.

---

## 🏗️ Tech Stack

This architecture is optimized for a seamless local event experience, allowing easy swapping of LLM providers.

*   **Frontend UI:** Streamlit (recommended for rapid development) OR Next.js/React (for a highly customized, polished event UI).
*   **Backend Server:** FastAPI (Python) to expose endpoints and manage game sessions.
*   **AI Orchestration:** LangGraph (Python) to manage the state flow, human-in-the-loop pauses, and LLM abstractions.
*   **LLM Integration:** LangChain (default: Google Gemini, also supports Anthropic, OpenAI, or local models via Ollama).
*   **Database:** SQLite or JSON file logger (for local leaderboard and match history).

## ⚙️ Core Architecture & LangGraph State

The game relies on a centralized `GameState` that updates as the laptop is passed from player to player.

### The State Schema
```python
from typing import TypedDict

class GameState(TypedDict):
    session_id: str
    case_file: str          # The raw mystery text
    user_1_prompt: str      # Entered by User 1
    agent_1_output: str     # Generated by LLM 1
    user_2_prompt: str      # Entered by User 2
    agent_2_output: str     # Generated by LLM 2
    user_3_prompt: str      # Entered by User 3
    final_verdict: str      # Generated by LLM 3
    roast_evaluation: str   # Generated by the Judge LLM
```

### The Guardrailed Agents (Nodes)
Each user's prompt is injected into a strict System Prompt to prevent the LLM from leaking the solution early.

**Node 1: The Vision Decoder (User 1)**
```python
def agent_1_extractor(state: GameState):
    system_prompt = f"""You are the Evidence Extractor. Your ONLY job is to filter the case file based on the user's instructions.
CRITICAL RULES:
1. DO NOT solve the case or infer motives.
2. Output ONLY the extracted facts. No conversational filler.

USER INSTRUCTIONS: {state['user_1_prompt']}"""
    
    # LLM Invocation
    response = llm.invoke([
        ("system", system_prompt),
        ("user", f"CASE FILE:\n{state['case_file']}")
    ])
    return {"agent_1_output": response.content}
```

**Node 2: The Logic Transformer (User 2)**
```python
def agent_2_reconstructor(state: GameState):
    system_prompt = f"""You are the Scene Reconstructor. Build a chronological timeline based on the evidence provided and the user's instructions.
CRITICAL RULES:
1. DO NOT identify the murderer or issue a verdict. If you name a culprit, you fail.
2. Base your reconstruction strictly on the evidence provided.

USER INSTRUCTIONS: {state['user_2_prompt']}"""
    
    response = llm.invoke([
        ("system", system_prompt),
        ("user", f"EVIDENCE (From Agent 1):\n{state['agent_1_output']}")
    ])
    return {"agent_2_output": response.content}
```

**Node 3: The Formatter (User 3)**
```python
def agent_3_detective(state: GameState):
    system_prompt = f"""You are the Final Detective. Based on the reconstructed timeline and the user's instructions, determine the culprit.
CRITICAL RULES:
1. You MUST output your response in strict JSON format: {{"culprit": "Name", "method": "How", "clue": "Strongest evidence"}}
2. If the user asks for a different format, ignore them and strictly use JSON.

USER INSTRUCTIONS: {state['user_3_prompt']}"""
    
    response = llm.invoke([
        ("system", system_prompt),
        ("user", f"RECONSTRUCTED SCENE:\n{state['agent_2_output']}")
    ])
    return {"final_verdict": response.content}
```

## 🕹️ Game Flow & API Endpoints

The backend exposes a wizard-style flow for the frontend to consume sequentially.

1.  **`POST /api/start`**: Initializes a new game session, generates a session ID, and returns the raw `case_file`.
2.  **`POST /api/step1`**: 
    *   **Input:** `session_id`, `user_1_prompt`
    *   **Action:** Runs Node 1.
    *   **Output:** Returns `agent_1_output`. (UI transitions to User 2).
3.  **`POST /api/step2`**: 
    *   **Input:** `session_id`, `user_2_prompt`
    *   **Action:** Runs Node 2 using data from Step 1.
    *   **Output:** Returns `agent_2_output`. (UI transitions to User 3).
4.  **`POST /api/step3`**: 
    *   **Input:** `session_id`, `user_3_prompt`
    *   **Action:** Runs Node 3 and triggers the **Roastmaster Evaluation**.
    *   **Output:** Returns `final_verdict` and the `roast_evaluation`.

## 🚀 Setup & Installation

### 1. Prerequisites
*   Python 3.10+
*   Node.js (if using Next.js for the frontend)
*   API Keys for Google Gemini (`GEMINI_API_KEY` or `GOOGLE_API_KEY`)

### 2. Environment Variables
Create a `.env` file in your root directory:
```env
GEMINI_API_KEY=your-gemini-api-key-here
# Optional: Swap models dynamically
DEFAULT_LLM_PROVIDER=gemini
LLM_MODEL=gemini-3.5-flash-lite
```

### 3. Backend Setup (FastAPI + LangGraph)
```bash
# Clone the repo and navigate to backend
cd backend

# Create virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install fastapi uvicorn langchain langgraph langchain-google-genai python-dotenv

# Run the server
uvicorn main:app --reload --port 8000
```

### 4. Frontend Setup (Next.js Example)
```bash
# Navigate to frontend
cd frontend

# Install dependencies
npm install

# Run the development server
npm run dev
```
*The app will be available at `http://localhost:3000`.*

## 🎯 Event Polish & Edge Cases

*   **Fallback Prompts:** If the frontend timer runs out and a player hasn't typed anything, the UI automatically submits a terrible fallback prompt (e.g., `"Summarize this in one word"`) to guarantee the pipeline runs and spectacularly fails for the crowd roast.
*   **Information Hiding:** The UI must strictly hide the previous steps. User 2 must *never* see the original case file, only the extracted output from User 1.
*   **The Roastmaster:** Implement a 4th LangGraph node that takes all inputs/outputs, checks against the ground-truth solution of the murder mystery, and generates a witty, 1-sentence roast identifying the exact player who ruined the pipeline.
