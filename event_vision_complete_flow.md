# 🎬 Prompt Relay: Event Vision & Complete Flow

## 🌟 The Core Vision
**Prompt Relay** is not just a coding challenge; it is a high-energy, spectator-friendly "esports" style game for tech meetups, hackathons, and conferences. 

The premise is simple but chaotic: **Teams of 3 have 5 minutes to solve a murder mystery by chaining together three AI agents.** 

The catch? They only get one laptop, they take turns in a "Hot Seat," and they cannot see what the previous teammate was supposed to look at. If one person's prompt is too vague or hallucinates, the entire pipeline collapses. The event concludes with an automated AI "Roastmaster" that publicly shames the exact teammate who ruined the chain.

The vibe is fast-paced, dramatic, and hilarious. Complexity is the enemy.

---

## 🎪 The Physical Event Setup
To make this work for a crowd, the physical space is divided into two views:

1. **The Stage (The Hot Seat):** A single podium on stage with one laptop. The 3 team members stand near the podium. Only one person types at a time.
2. **The Jumbotron (The Crowd View):** A large projector/screen behind the team. This screen displays a spectator dashboard showing the team's progress, the ticking countdown timer, the live text streaming from the LLMs, and ultimately, the final Roast.

---

## 👥 The Roles (The 3-Agent Pipeline)
A team consists of three players, each acting as a human "manager" for a specific AI agent in a sequential pipeline.

* **Player 1: The Vision Decoder (Extractor)**
  * **Their input:** A massive, chaotic "Case File" full of useless noise (e.g., coffee orders, weather reports) and vital clues (weapons, times).
  * **Their goal:** Write a prompt that forces the AI to extract *only* the relevant facts without accidentally solving the case or hallucinating.
* **Player 2: The Logic Transformer (Reconstructor)**
  * **Their input:** ONLY the output generated by Player 1's AI. (They never see the original Case File).
  * **Their goal:** Write a prompt that forces the AI to build a chronological timeline from the clues, while strictly avoiding naming the killer. 
* **Player 3: The Formatter (Detective)**
  * **Their input:** ONLY the timeline generated by Player 2's AI.
  * **Their goal:** Write a prompt that analyzes the timeline, names the killer, and forces the AI to output the final answer in a strict JSON format (`{"culprit": "...", "method": "...", "clue": "..."}`).

## ⏱️ The Minute-by-Minute Experience (A Single Match)

Here is exactly what happens when a team steps up to play:

### 0:00 - 0:30 | The Walk-Out & Briefing
* The MC calls the team to the stage.
* The Jumbotron displays the team name and the rules. 
* Player 1 steps up to the laptop. Players 2 and 3 face away or step back.

### 0:30 - 2:00 | Step 1: The Extraction (90 Seconds)
* **The UI:** Player 1's screen reveals the messy Case File. A 90-second timer begins ticking down aggressively.
* **The Action:** Player 1 frantically types a system prompt (e.g., *"Extract all times and objects, ignore the dialogue about cats"*). 
* **The Crowd:** The Jumbotron shows the timer and Player 1's live typing.
* **Time's Up:** If the timer hits zero, the UI auto-submits. The AI processes the prompt, and the stage screen flashes **"LINK 1 COMPLETE."**

### 2:00 - 3:30 | Step 2: The Reconstruction (90 Seconds)
* **The Switch:** Player 1 steps away. Player 2 jumps into the Hot Seat.
* **The UI:** The original Case File is GONE. Player 2 only sees what Player 1's AI spit out. If Player 1's prompt was bad, Player 2 sees garbage data.
* **The Action:** Player 2 types a prompt to build a timeline (e.g., *"Put these events in order. Do not say who the killer is."*)
* **Time's Up:** The UI auto-submits. The AI processes. The stage screen flashes **"LINK 2 COMPLETE."**

### 3:30 - 4:30 | Step 3: The Verdict (60 Seconds)
* **The Switch:** Player 2 steps away. Player 3 jumps into the Hot Seat. 
* **The UI:** Player 3 only sees Player 2's timeline.
* **The Action:** Player 3 must write the final prompt to catch the killer AND format it perfectly. (e.g., *"Who is the killer? Output ONLY valid JSON with keys: culprit, method, clue"*).
* **Time's Up:** The UI auto-submits.

### 4:30 - 5:00 | The Reveal & The Roast (The Climax)
* **The Live Stream:** The Jumbotron takes over completely. The crowd watches as the final AI verdict streams live onto the big screen token-by-token.
* **The Judging:** The backend "Roastmaster AI" analyzes the entire pipeline.
* **The Result:** 
    * **If they win:** Green confetti on screen! "The killer was caught!" 
    * **If they lose (The Roast):** A giant red siren. The screen reveals exactly who messed up. 
    * *Example Crowd Screen:* **"PIPELINE FAILURE. Player 2 leaked the killer early. The Roastmaster says: 'Player 2, you were supposed to build a timeline, not be the judge, jury, and executioner. Way to ruin it for everyone.'"**
* The crowd cheers/laughs, the team walks off, and the next team is called up.

## ⚠️ "Gotchas" & Why the Game is Fun (For Organizers)

To ensure maximum drama, the system is rigged with invisible "System Prompts" that wrap the user's input. We *want* teams to fail if they aren't careful. 

* **The Leak Trap:** If Player 2's prompt isn't strict, their AI might accidentally name the killer. If this happens, the backend detects it and auto-fails the team.
* **The Format Trap:** If Player 3 writes a great prompt but forgets to say "Do not include markdown tags" or "Output strictly JSON," the pipeline breaks.
* **The Panic Fallback:** If a player freezes and the timer hits zero with an empty text box, the system injects a terrible hidden prompt (e.g., `"Summarize this case in three emojis"`) guaranteeing a hilarious failure for the next player in line.

## 🤝 Onboarding Note for Developers
If you are touching the codebase for the first time, keep this event flow in mind. 
1. **Frontend Devs:** Focus on making the UI highly legible from 20 feet away (for the Jumbotron view) and creating aggressive, stressful visual indicators for the Hot Seat laptop (big red timers, flashing warnings).
2. **Backend/AI Devs:** Focus on making the LangGraph state transitions lightning fast. We cannot have the crowd waiting 30 seconds for an API response. Use fast models (default: Google Gemini `gemini-3.5-flash-lite` or Claude Haiku) and keep the system prompt wrappers tight.
